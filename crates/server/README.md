# ratatosk-server

Сервер h3-транспорта ratatosk (QUIC, свой протокол): план и причины в [docs/h3-transport-plan.md](../../docs/h3-transport-plan.md). Прототип, стадия 2.

Что умеет сейчас: QUIC v1 + TLS 1.3 с сертификатом домена из файлов, ALPN `h3`, аутентификация токеном от uuid, привязанным к TLS-сессии, TCP-цели как потоки одного соединения, UDP как QUIC DATAGRAM (RFC 9221) в том же соединении (пакет больше лимита датаграммы пути идёт фрагментами, до 8; свой UDP-сокет на каждую сессию клиента, до 256 на соединение, закрытие после 2 минут тишины), отказ в доступе к приватным адресам. Обычные HTTP/3-клиенты получают контент внешнего HTTP-backend. ACME внутри сервера пока нет: сертификат получает Caddy либо оператор передаёт готовые файлы.

Начальный MTU 1350 вмещает 1200-байтовый QUIC Initial приложений, дальше потолок поднимает поиск MTU пути. Пакет больше текущего потолка передаётся фрагментами, до восьми; потеря фрагмента означает потерю исходного пакета.

```toml
# server.toml
listen = "0.0.0.0:8445"
cert = "/etc/letsencrypt/live/example.com/fullchain.pem"
key = "/etc/letsencrypt/live/example.com/privkey.pem"
users = ["00000000-0000-0000-0000-000000000000"]
site_backend = "http://caddy:8080"
# allow_private = false
# max_connections = 1024          # живых соединений суммарно
# max_incoming = 1024             # незавершённых рукопожатий в очереди quinn
# max_connections_per_ip = 16     # соединений с одного адреса
```

```sh
cargo build --release -p ratatosk-server
target/release/ratatosk-server -c server.toml        # -v для подробного лога
```

Ссылка для клиента: `h3://<uuid>@example.com:8445?sni=example.com#name` — подходит для `ratatosk`, файла ссылок и подписок.

## Ограничения ресурсов

QUIC-эндпоинт принимает пакеты от кого угодно, поэтому у него есть пределы,
включаемые по умолчанию (менять в `server.toml`, значения в скобках):

- `max_connections` (1024) — живых соединений суммарно. Новое рукопожатие
  получает слот только после того, как завершится чужое.
- `max_incoming` (1024) — незавершённых рукопожатий, которые quinn буферизует
  до отказа. Остальное отбрасывается без выделения памяти.
- `max_connections_per_ip` (16) — соединений с одного адреса; лишние
  отклоняются до рукопожатия. Обход через смену IP упирается в два предела выше.
- Ноль в любом из полей отвергается при старте: незамеченный ноль молча
  выключил бы соответствующий предел.

Попутно всегда включены пределы на соединение и меры против усиления:

- ответ `Retry` до рукопожатия — клиент должен доказать, что адрес его, иначе
  спуфинг-флуд не превращается в усилитель;
- окно приёма 4 МиБ на соединение и 256 КиБ на поток (умолчание quinn —
  `VarInt::MAX`, то есть один клиент мог заставить сервер буферизовать много);
- не больше 64 двунаправленных потоков на соединение;
- 256 UDP-сессий на соединение, закрытие после 2 минут тишины.

Исчерпание любого предела пишется в лог на уровне `debug`
(`per-IP connection limit reached`), отказы по таймаутам рукопожатия — тоже.
Слот освобождается, когда задача соединения кончается: при живом клиенте это
закрытие по `CONNECTION_CLOSE`, после аварийного завершения — не позже
30-секундного `IDLE_TIMEOUT` (30 s здесь работают как верхняя граница для
мёртвых слотов, а не только для простоя).

`site_backend` — HTTP origin без пути, логина и пароля. Получение страницы
не требует UUID. Поддерживаются GET/HEAD, пересылка Range и условных заголовков,
статусы и потоковая выдача тела ответа. Другие методы получают 405; без backend
сервер возвращает нейтральный 404, при его недоступности — 502.
Редиректы передаются браузеру. При необходимости отдавать видео с этого домена
backend должен выдавать локальные ссылки на медиаресурсы.

Страница и настройки продуктивного сайта находятся в отдельном закрытом
репозитории. Серверный бинарник и образ их не включают.

На измерительном стенде порт транспорта остаётся 8445/udp, Caddy — на 443.
Проверка именно серверного HTTP/3-обработчика:

```sh
curl --http3-only --connect-to example.com:443:example.com:8445 https://example.com/
```

Переход на общий публичный TCP/UDP 443 требует отдельной настройки Caddy,
port mappings и Alt-Svc; эта схема пока не развёрнута. Уже созданный
`h3-server.toml` нужно дополнить `site_backend` вручную: повторный запуск
`setup.sh` перезаписывает сгенерированные конфиги.
