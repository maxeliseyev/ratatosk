# Comparison: baseline → после правок (фазы 1–4)

Измерения после всех правок ядра (nodelay/keepalive, network_changed) и клиентов
(epoll+eventfd на Android, адаптивный поллинг на Android/iOS).

## Desktop (macOS, `crates/core/examples/bench.rs`, релиз)

| Метрика | baseline | after | Δ |
|---|---|---|---|
| idle_cpu_pct | 0.003 % | 0.004 % | ≈ 0 |
| cpu_per_mbit (с) | 0.000063 | 0.000069 | ≈ 0 (шум) |
| rss_idle_mb | 7.3 | 7.4 | ≈ 0 |
| rss_load_mb | 8.5 | 8.6 | ≈ 0 |

## Android (Redmi Note 8 Pro, APK v6, экран выкл, 300 с)

| Метрика | baseline | after | Δ |
|---|---|---|---|
| idle_cpu_pct | 0.62 % | 0.68 % | ≈ 0 (шум фонового трафика) |
| pss_kb | 72 996 | 72 361 | ≈ 0 |
| **reader wakeups / 60 с** | **~300** | **1** | **−99.7 %** |

## Что реально изменилось

Idle CPU% **не** изменился значимо — он задан фоновым трафиком телефона
(Play Services, мессенджеры), а не нашим кодом. Выигрыш — в другом:

1. **Пробуждения reader-потока: ~300 → 1 за минуту** (epoll+eventfd вместо
   `poll(200ms)`). Поток больше не будит CPU 5 раз/сек «просто так», поэтому
   CPU уходит в глубокие C-states — это прямая экономия батареи в простое.
2. **TCP_NODELAY + keepalive**: убирает Nagle-задержку (~40 мс на мелких
   запросах) и детектит мёртвый путь за ~50 с вместо часов (валидация — на
   реальном TCP-сервере, loopback её не показывает).
3. **network_changed**: Mux-соединения инвалидируются при смене Wi-Fi↔LTE,
   новые сессии диалят свежий handshake вместо записи в мёртвый сокет.
4. **Адаптивный поллинг**: UI-статистика 1 с при трафике, 3 с в тишине.

## Сравнение с PORTAL_WG (контекст изначального разбора)

| | PORTAL_WG | Ratatosk |
|---|---|---|
| Процессы | 3 (UI + mihomo/tgwss + gVisor-бэкенд) | 1 |
| Рантайм | Go (GC), ~100+ МБ на процесс | Rust, ~71 МБ PSS всего |
| Поллинг | 3 с в фоне постоянно | только UI на экране, 1–3 с |
| Idle-пробуждения | 5/с (poll) + фоновые сервисы | 0.02/с (epoll) |
| Обфускация | AmneziaWG мусорные пакеты (73–432/handshake) | REALITY (0 лишнего трафика) |

## Вывод

Ядро и так было экономным (idle ≈ 0 на desktop); правки фаз 1–4 не добавили
накладных расходов (CPU/RSS без изменений) и убрали главный источник лишних
пробуждений на мобильной стороне (reader poll → epoll, −99.7 %).
